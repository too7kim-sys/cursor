# 웹스퀘어(WebSquare/W-Frame) 화면/컴포넌트 패턴

웹스퀘어 화면(.xml/.wsq)·스크립트(.js) 작업 시 따를 규칙. XML 구조와 디자이너 호환성을 **보존**.

> ⚠️ 화면은 WebSquare 디자이너로 편집됩니다. 텍스트 수정 시 태그/네임스페이스/속성 형식을
> 유지하고, 수정 후 디자이너에서 열어 검증하세요.

## 1. 구조 / 명명 규칙(관례)
- 컴포넌트 id 접두어 관례: Button `btn_`, input `ipt_`/`edt_`, select `sel_`, grid `grd_`,
  dataCollection/dataList `dl_`/`dc_`, group `grp_`.
- 데이터는 **DataList/DataMap** 에 두고 컴포넌트에 바인딩(`ref`/dataCollection 연결).

## 2. 데이터 / 통신
- 서버통신은 `WebSquare.ajax` / submission(트랜잭션) 사용. 조회 → 데이터컬렉션 갱신 → 그리드 반영.
- 그리드 편집상태(추가/수정/삭제)는 DataList 상태로 관리 후 저장 submission.

## 3. 현대적 UX 적용 포인트
- **조회 화면**: 검색조건 영역 + [조회][초기화] + 그리드 + 건수/페이징.
- **빈 결과**: 그리드 no-data 메시지 설정 또는 안내 영역 표시.
- **로딩**: 통신 중 blockUI/진행표시, 버튼 비활성으로 중복요청 방지.
- **검증**: 저장 전 필수/형식 검증 → 첫 오류로 focus 이동 + 메시지.
- **확인/알림**: 삭제·저장은 confirm 후 진행, 완료는 비차단 알림(스낵바/토스트 류).
- **접근성/일관성**: 라벨 연결, 탭 순서, 공통 CSS/테마 사용(인라인 스타일 남발 금지).

## 4. 공통화
- 공통 스크립트(메시지/통신 래퍼/그리드 공통포맷)와 공통 화면(헤더/검색영역 템플릿) 재사용.
- 하드코딩 대신 공통코드/공통컴포넌트 활용.

## 5. 작업 절차(AI 지침)
1. `search_text`/`semantic_search` 로 **유사 화면(.xml/.wsq)** 과 공통 스크립트를 먼저 확인.
2. 같은 명명/바인딩/통신 패턴을 따른다.
3. XML 구조·네임스페이스·속성 형식 보존. 새 컴포넌트는 기존 정의를 복제해 추가.
4. 큰 화면 파일은 `read_file` 의 start_line/end_line 으로 필요한 영역만 확인.
