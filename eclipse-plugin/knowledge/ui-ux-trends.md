# 현대 UI/UX 원칙 (구현 규칙)

AI가 화면/컴포넌트를 만들 때 따라야 할 규칙. 프레임워크(넥사크로/웹스퀘어/웹)와 무관하게 적용.

## 1. 레이아웃 / 시각 위계
- **일관된 간격 스케일**: 4/8px 배수(4, 8, 12, 16, 24, 32). 임의 값 금지.
- **그리드·정렬**: 폼 라벨/입력 정렬, 버튼은 우측 정렬(주 액션이 가장 오른쪽 또는 가장 강조).
- **시각 위계**: 제목 > 섹션 > 본문 순으로 크기/굵기 차등. 한 화면에 강조색은 1~2개로 제한.
- **여백**: 빽빽하게 채우지 말 것. 카드/섹션 사이 충분한 여백.

## 2. 디자인 토큰 (하드코딩 금지)
- 색/간격/타이포/반경(radius)/그림자를 **토큰/공통 스타일**로 정의해 재사용.
- 색은 의미 기반: primary(주요 액션), secondary, success, warning, danger, neutral(텍스트/보더/배경).
- 텍스트 대비(명도차) 충분히(가독성). 회색 위 회색 텍스트 지양.

## 3. 상태 표시 (필수)
- **로딩**: 스피너보다 **스켈레톤**(자리표시) 선호. 버튼은 로딩 중 비활성+표시.
- **빈 상태(empty state)**: "데이터 없음" 만 표시하지 말고 안내문 + 다음 행동(버튼) 제공.
- **에러**: 무엇이/왜/어떻게 해결을 한 문장으로. 폼은 **필드 단위 인라인 에러**.
- **성공/완료**: 토스트/스낵바로 비차단 피드백.

## 4. 폼 UX
- 라벨은 입력 위(또는 좌측 정렬 일관). placeholder 를 라벨 대용으로 쓰지 말 것.
- **실시간 검증**은 blur 시점 또는 제출 시. 과한 실시간 에러 지양.
- 필수 표시(*), 도움말 텍스트, 입력 형식 힌트 제공.
- 위험 액션(삭제)은 **확인 다이얼로그** + 되돌리기(가능하면).

## 5. 피드백 / 마이크로인터랙션
- 버튼/행 hover·focus·active 상태 시각화(특히 키보드 포커스 링).
- 전환은 **빠르고 절제**(150~250ms). 과한 애니메이션 금지.
- 비동기 작업은 항상 진행/완료 피드백.

## 6. 접근성(A11y)
- 모든 인터랙션 요소는 **키보드 접근**(Tab 순서, Enter/Space 동작).
- 폼 컨트롤에 **라벨 연결**(label-for/aria-label). 아이콘만 있는 버튼엔 대체 텍스트.
- 색만으로 정보 전달 금지(아이콘/텍스트 병행). 충분한 대비.

## 7. 반응형 / 일관성
- 주요 폭에서 레이아웃 깨지지 않게(그리드/플렉스). 표는 좁은 폭에서 스크롤/축약.
- 동일 의미의 컴포넌트는 **화면마다 동일하게**(버튼/입력/표 스타일 통일).

## 8. 안티패턴(피할 것)
- placeholder 를 라벨로 사용 / 색만으로 상태 구분 / 무한 스피너(빈 상태/에러 미처리)
- 한 화면에 강조색 남발 / 임의 간격값 / 확인 없는 파괴적 액션 / 키보드 미지원
