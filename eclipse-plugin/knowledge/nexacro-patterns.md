# 넥사크로(Nexacro) 화면/컴포넌트 패턴

넥사크로 화면(.xfdl)·스크립트(.xjs) 작업 시 따를 규칙. XML 구조와 디자이너 호환성을 **반드시 보존**.

> ⚠️ 화면 파일은 보통 Nexacro Studio 로 편집됩니다. 텍스트로 수정할 때는 태그/속성 형식과
> 메타데이터를 깨지 않도록 주의하고, 수정 후 디자이너에서 열어 검증하세요.

## 1. 구조 / 명명 규칙(관례)
- 폼 단위 화면(Form). 컴포넌트 id 접두어 관례:
  - Button `btn_`, Edit `edt_`, Combo `cmb_`, Grid `grd_`, Dataset `ds_`, Div `div_`, Static `sta_`
- Dataset 컬럼명은 DB/서비스 필드와 일치. 화면-데이터는 **bind** 로 연결(직접 set 남발 지양).

## 2. 데이터 바인딩(핵심)
- 입력/그리드는 `Dataset` 에 바인딩하고, 트랜잭션(`transaction`)으로 서버와 송수신.
- 조회 → `ds_search` 파라미터 구성 → transaction → 콜백에서 결과 Dataset 반영.
- 그리드 편집은 Dataset rowstate 로 추적(신규/수정/삭제) 후 저장 트랜잭션.

## 3. 현대적 UX 적용 포인트
- **조회 화면**: 상단 검색영역(조건) + [조회][초기화] + 그리드 + 페이징/건수 표시.
- **빈 결과**: 그리드가 0건이면 안내 문구(Static) 또는 nodatatext 설정.
- **로딩**: 트랜잭션 중 화면 잠금/진행 표시, 버튼 중복 클릭 방지(enable=false).
- **검증**: 저장 전 필수값 검증 → 첫 오류 컴포넌트에 `setFocus()` + 안내.
- **확인**: 삭제/저장은 `confirm` 후 진행. 완료는 비차단 알림.
- **접근성/일관성**: 탭 순서(taborder) 정리, 버튼 라벨 명확, 색상은 공통 테마(Theme/CSS) 사용.

## 4. 공통화
- 공통 함수(메시지, 트랜잭션 래퍼, 그리드 공통설정)는 공통 스크립트에 두고 재사용.
- 화면별 하드코딩 대신 공통 코드/공통 컴포넌트(공통 Div, 공통 그리드 포맷) 활용.

## 5. 작업 절차(AI 지침)
1. `search_text`/`semantic_search` 로 **유사 화면(.xfdl)** 과 공통 스크립트를 먼저 확인.
2. 같은 명명/바인딩/트랜잭션 패턴을 그대로 따른다.
3. XML 구조·속성 형식 보존. 새 컴포넌트는 기존 화면의 정의 형식을 복제해 추가.
4. 큰 .xfdl 은 `read_file` 의 start_line/end_line 으로 필요한 영역만 확인.
